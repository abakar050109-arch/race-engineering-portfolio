# Как выложить это на GitHub

Пошагово, с нуля. Займёт один вечер.

## Шаг 0. Что уже есть и чего нет

Проверил твою машину:

- **Python 3.11** — есть.
- **git** — **нет**.
- **GitHub CLI (`gh`)** — **нет**.
- Аккаунт GitHub — надо проверить, есть ли.

То есть пока «поделиться на GitHub» технически невозможно: нечем отправлять файлы.

## Шаг 1. Поставить Git (обязательно)

Скачай **Git for Windows**: https://git-scm.com/download/win

Установка — везде «Next», но на шаге выбора редактора можно оставить по умолчанию. После установки **перезапусти PyCharm** (и перезагрузи компьютер, если git не появится в терминале).

Проверка: открой терминал и напиши `git --version`. Должно ответить что-то вроде `git version 2.47.0`.

## Шаг 2. Завести аккаунт GitHub

https://github.com/signup

**Ник выбирай серьёзно** — он попадёт в резюме и в ссылку, которую ты будешь отправлять командам. Не `xx_gamer_2010`, а например `a.suleymanov` или `abakar-race-eng`.

## Шаг 3. Поставить GitHub Desktop (проще, чем командная строка)

https://desktop.github.com

Почему не командная строка: на первом курсе тебе важнее понять *что* происходит с файлами, а не выучить двадцать команд. Desktop показывает изменения глазами. Командную строку освоишь позже, когда появится привычка.

После установки: войди в свой аккаунт GitHub.

## Шаг 4. Создать репозиторий

В GitHub Desktop: **File → Add local repository** → выбери папку:

```
C:\Users\user\OneDrive\Документы\deepseek-harness\default-workspace\race-engineering-portfolio
```

Он скажет, что это не git-репозиторий, и предложит создать — соглашайся.

Дальше **Publish repository**:
- Name: `race-engineering-portfolio`
- Description: `Telemetry analysis and race engineering projects`
- **Сними галочку** «Keep this code private» — репозиторий должен быть публичным, иначе команда его не увидит.

## Шаг 5. Первый коммит

Он появится сам при публикации. Дальше правило: **один осмысленный шаг — один коммит.**

Плохо: `update`, `fix`, `123`.
Хорошо: `Add lap detection by distance`, `Fix speed units m/s to km/h`.

## Шаг 6. Про данные

Файлы `data.csv` на 56 МБ **в репозиторий не пойдут** — для этого уже настроен `.gitignore`. GitHub не любит большие файлы, а команде не нужен твой лог — ей нужен код и вывод.

Данные храни отдельно. Если очень нужно показать — приложи скриншот графика в `docs/`.

## Шаг 7. Что проверить перед первым «показать людям»

- [ ] README на английском, без ошибок (прогони через проверку орфографии).
- [ ] Нет паролей, токенов, личных путей вида `C:\Users\user\...` в коде.
- [ ] Нет файлов `.venv`, `f1_cache`, `__pycache__`.
- [ ] В каждом проекте есть раздел «Вывод».
- [ ] Ты можешь объяснить каждую строку своего кода.

## Если что-то не получается

Типичные ошибки:

**`git: command not found`** — не перезапустил терминал после установки.

**`Permission denied (publickey)`** — GitHub Desktop сам настраивает ключи, поэтому через него проще, чем через командную строку.

**«File is too large»** — в коммит попал CSV. Убери его: `git rm --cached data.csv`, проверь `.gitignore`, закоммить заново.

**Русские имена файлов ломаются** — переименуй файлы и папки в репозитории на латиницу. Внутри кода тоже лучше латиница.
